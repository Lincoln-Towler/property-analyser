# Property Analyser — working notes for Claude

Personal Australian property investment dashboard. Solo hobbyist project
(Lincoln). Read this before changing anything.

## Where the code lives

| Path | What it is |
|---|---|
| `web/` | **The live site.** Next.js 15 App Router + Tailwind 4 + Recharts. Deployed on Vercel (root directory = `web`). This is the thing being built. |
| `web/src/lib/scoring/` | The market score engine — the project's core IP, a TypeScript port of the Python. |
| `supabase/migrations/` | Schema. Owns the DB; app code must never run DDL. |
| `property_analysis_dashboard.py` | **Legacy Streamlit app**, ~5,300 lines. Being replaced. Still running in parallel during cutover; still the parity reference. Do not add features here. |
| `obsidian-vault/` | The user's notes. Keep `Changelog.md` current. |

## Deployment — how a change reaches the site

1. Commit to the designated branch (`claude/…`) and push.
2. **The user merges the PR into `main`.**
3. Vercel auto-deploys from `main`. Pages use ISR (`revalidate = 3600`), so
   a deploy is what makes a change visible, not a page refresh.
4. A nightly Vercel Cron hits `/api/snapshot`, which computes the score and
   upserts one row into `market_score_history`.

**Nothing is live until the user merges.** If they say "I can't see X",
check `git log origin/main` first — then whether Vercel redeployed.

## Non-negotiables

### Never modify the user's data to make a problem go away
An August 2026 audit proposed deleting 31 "outlier" readings. An adversarial
review rejected **every single deletion** — several accusations contained
arithmetic errors (e.g. calling Brisbane's −30.93% growth impossible by
comparing two non-overlapping windows). The standing rule: **surface
anomalies, never delete them.** `web/src/lib/property-audit.ts` and the
`/audit` page are the mechanism. Read-time filtering (`transforms.ts`) is
acceptable; row deletion is not.

Values that look impossible often aren't: "locations" mix capitals, suburbs
and regional towns at different geographic scopes, so Sydney's Feb snapshot
(sales_volume 13, DOM 106) is a sub-market sample, not a city-wide figure.

### The scoring engine is parity-tested — respect it
`web/tests/scoring.parity.test.ts` pins the TS engine against fixtures
generated by running the **real Python engine** (`web/tests/generate_fixtures.py`).
The port is deliberately **bug-for-bug**; see the PARITY NOTE at the top of
`engine.ts` for the preserved quirks.

Any change to scoring maths:
1. is its own reviewed commit,
2. regenerates fixtures,
3. records the before/after score delta for the user to sign off.

Prefer display-only additions that leave scoring untouched — that is how
`getWindowContext` and the cadence flags were added.

### Don't invent data
Published figures differ wildly by methodology — Australian household
debt-to-GDP spans 108–120% across IMF / ABS / CEIC for the *same quarter*,
crossing this project's own warning (110) and danger (120) thresholds.
The user's series is **ABS 5232.0** (the 113.x family). Never mix sources
inside one series; never fill a gap with a plausible-looking number.
`supabase/backfill-indicator.sql` is the template.

## Decisions already made (don't relitigate)

- **Anderson cycle anchor: 2008.** Unified June 2026; puts 2026 at Year 18,
  Crash phase. The old Streamlit page used 2011.
- **Next.js over a static site** — chosen for a live site with instant
  refresh after edits.
- **Zero-valued readings are real values, not absences.** `locationScore`
  uses a presence check, matching `calculateRegionalDivergence`. The Python's
  `if x and x > n` idiom was a None-check, not a decision about zero.
- **Location Analysis was deferred, then rebuilt** (`/locations`) once the
  user added an August 2026 snapshot for all 12 locations.

## Known open issues

- **n8n interest_rate scrape has been dead since 2026-07-16** (wrote literal
  `0` weekly until a DB guard stopped it). The user is fixing n8n. Migration
  `0006` rejects implausible values; history rows are dropped silently, which
  shows up as staleness on `/audit`.
- **~43% of the score rides on data that cannot move.** Shown on `/audit`.
  `household_debt_gdp` alone is 18.5% off one 404-day-old reading.
- **Quarterly indicators can never trend or register volatility** — the
  engine needs 2 readings in 3 months / 3 in 6 months; a quarterly cadence
  supplies 1 and 2. Backfilling cannot fix this; only frequency-aware
  windows would (a scoring change, not yet authorised). Pinned by a test in
  `window-context.test.ts`.
- **The two-point trend rule is blind on weekly series** — auction clearance
  fell 17% over six readings and scored "stable". `getWindowContext` surfaces
  the contradiction without changing the score.

## Conventions

- Run `npm test` (vitest) and `npx tsc --noEmit` in `web/` before committing.
- Migrations are numbered and idempotent where possible; the free tier has
  **no automated backups**, so destructive SQL needs a manual export first.
- Supabase access is via the MCP connector, which drops in and out between
  sessions. If it is unavailable, write the migration file and hand the user
  the SQL rather than blocking.
- The user is not a developer — explain in plain language, spell out
  click-by-click steps, and never assume they will read code comments.
